## Project Overview

**n8n-nodes-rckflr-sqlitemanager** is a community node package for n8n that enables SQLite database management and vector search capabilities directly within n8n workflows.

### Key Features
- Local SQLite database file management (list, create, delete)
- SQL query execution with JSON result parsing
- Vector search via sqlite-vec extension integration
- File system security with path traversal protection
- Support for n8n's "continue on fail" pattern

### Use Cases
- Lightweight knowledge bases for AI agents
- Shared workflow cache tables
- Ad-hoc data migrations and maintenance scripts
- Vector similarity search for embeddings

## Code Architecture

### Main Entry Point
`nodes/SqliteManager/SqliteManager.node.ts` implements the `INodeType` interface required by n8n.

### Core Components

#### 1. Node Class: `SqliteManager`
```typescript
export class SqliteManager implements INodeType {
  description: INodeTypeDescription;  // n8n node metadata
  async execute(this: IExecuteFunctions): Promise<INodeExecutionData[][]>;
}
```

#### 2. Operations
The node supports four operations (enum type: `Operation`):
- `listDatabases`: Enumerate SQLite files in `SQLITE_BASE_DIR`
- `createDatabase`: Create new database with optional bootstrap SQL
- `deleteDatabase`: Remove database file
- `executeQuery`: Run arbitrary SQL with optional JSON result parsing

#### 3. Helper Functions

**Path Security**
- `resolveBaseDir()`: Returns configured base directory
- `normalizeDatabaseName(rawName)`: Validates and sanitizes database names
- `safeResolveDatabasePath(baseDir, dbName)`: Prevents path traversal attacks
- `ensureBaseDir(directory)`: Creates base directory if missing

**File Operations**
- `fileExists(filePath)`: Non-throwing file existence check

**SQLite Interaction**
- `runSqliteCommand(args, sql?, options?)`: Spawns `sqlite3` CLI process
  - Supports `-cmd .load` for sqlite-vec preloading
  - Handles stdin piping for SQL execution
  - Returns structured `{ stdout, stderr }` result

### Security Considerations

**Path Traversal Protection**
- Database names are validated against regex: `/^[\w.-]+$/`
- Path separators (`/`, `\`) and `..` segments are rejected
- Resolved paths must be within `SQLITE_BASE_DIR`

**Allowed Extensions**
Only `.db`, `.sqlite`, `.sqlite3` files are recognized.

**No SQL Injection Protection**
The node executes SQL as-is via CLI. Users are responsible for parameterization or sanitization in their workflows.

## Code Style and Conventions

- **Indentation**: Tabs (width 2)
- **Line Width**: 100 characters
- **Quotes**: Single quotes
- **Semicolons**: Required

- **Arrow Functions**: Always use parentheses

### TypeScript Settings
- **Strict Mode**: Enabled
- **Target**: ES2019
- **Module**: CommonJS
- **No Implicit Any**: Enforced
- **Unused Locals**: Error

### Naming Conventions
- **Files**: PascalCase for classes (`SqliteManager.node.ts`), kebab-case for configs
- **Classes**: PascalCase (`SqliteManager`)
- **Functions**: camelCase (`resolveBaseDir`, `normalizeDatabaseName`)
- **Constants**: UPPER_SNAKE_CASE (`DEFAULT_BASE_DIR`, `ALLOWED_EXTENSIONS`)
- **Types**: PascalCase (`Operation`, `SqliteCommandResult`)

### Error Handling
- Use `ApplicationError` for user-facing errors
- Use `NodeOperationError` for n8n-specific errors with item index
- Support `this.continueOnFail()` pattern by catching and returning error objects

### Code Organization
- Utility functions before class declaration
- Class structure:
  1. `description` property (node metadata)
  2. `execute()` method (node logic)
- Switch statements for operation routing

## n8n Node Conventions

### Node Metadata Structure
```typescript
description: INodeTypeDescription = {
  displayName: string;           // User-facing name
  name: string;                  // Internal identifier (camelCase)
  icon: { light: string, dark: string };  // SVG icons
  group: ['transform'];          // Node category
  version: number;               // Schema version
  inputs: ['main'];              // Input connection types
  outputs: ['main'];             // Output connection types
  usableAsTool: boolean;         // AI agent tool compatibility
  properties: INodeProperties[]; // Parameter definitions
}
```

### Parameter Patterns
- **Operation Selector**: First parameter, type `options`, no data expressions
- **Conditional Display**: Use `displayOptions.show` to toggle based on operation
- **Required Fields**: Set `required: true` and validate in code
- **Text Areas**: Use `typeOptions: { rows: N }` for multiline inputs

### Data Flow
- Input: `this.getInputData()` returns `INodeExecutionData[]`
- Parameters: `this.getNodeParameter(name, itemIndex)`
- Output: Return `INodeExecutionData[][]` (array of result sets)
- Loop over items even if array is empty (use `loopItems` fallback)

### Best Practices
- Preserve original item data: `{ ...loopItems[itemIndex].json, ...newData }`
- Use `pairedItem` for error tracking
- Return structured JSON with consistent field names
- Provide meaningful error messages

## SQLite-vec Integration

### How It Works
1. Environment variables specify library path and entry point
2. `runSqliteCommand()` prepends `-cmd .load <path> <entry>` to args
3. sqlite3 CLI loads the extension before executing SQL
4. Vector search syntax (e.g., `WHERE embedding MATCH ...`) becomes available

### Testing Vector Functionality
The e2e test validates:
- Extension loading succeeds
- `vec0` virtual table creation works
- KNN queries return correct results
- JSON output parsing handles vector data

### Common Issues
- **Library not found**: Check `SQLITE_VEC_LIBRARY` path
- **Wrong architecture**: Compile sqlite-vec for target platform
- **Entry point mismatch**: Verify `SQLITE_VEC_ENTRYPOINT` matches compiled library
- **CLI version**: Ensure sqlite3 ≥ 3.49 with extension support

## Debugging

### VS Code Configuration
`.vscode/launch.json` provides debug configuration for local n8n development.

### Common Issues

**Build Fails**
- Check TypeScript version: `pnpm list typescript`
- Clear `dist/` folder: `rm -rf dist && pnpm build`

**Lint Errors**
- Auto-fix: `pnpm lint:fix`
- Check `.prettierrc.js` and `eslint.config.mjs`

**Node Not Appearing in n8n**
- Verify `n8n` field in `package.json`
- Check `dist/` contains compiled files
- Restart n8n after installation

**Path Errors**
- Ensure `SQLITE_BASE_DIR` exists and is writable
- Check file permissions
- Verify no special characters in database names
